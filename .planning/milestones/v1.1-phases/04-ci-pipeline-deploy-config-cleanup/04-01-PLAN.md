<threat_model>
Security enforcement is on for this project at OWASP ASVS level 1, blocking on `high`. This phase's genuine new surface is the GitHub Actions workflow itself — the repo just went public, so this is a real, not theoretical, boundary.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public GitHub repo -> GitHub Actions runner | Any push to `main`, and any `pull_request` (including from a fork, since the repo is public), triggers a workflow run with a `GITHUB_TOKEN` |
| Third-party GitHub Actions -> the runner environment | `actions/checkout@v4` and `actions/setup-node@v4` are first-party GitHub actions, but any action pulled from the marketplace executes with the permissions granted to the job |
| Deleted deploy-config files -> git history | `netlify.toml`/`wrangler.toml` are removed from HEAD but remain recoverable from git history — confirmed during planning that neither file ever contained a secret, so this is not a credential-exposure concern |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01-01 | Elevation of Privilege | `.github/workflows/ci.yml`'s `GITHUB_TOKEN` | high | mitigate | Task 1 sets an explicit top-level `permissions: contents: read` — without it, a public repo's default token can carry broader (write) scope than any step in this workflow needs. No step writes to the repo, deploys, or calls any API requiring elevated access. |
| T-04-01-02 | Tampering | `pull_request` trigger accepting forked-repo PRs | medium | mitigate | Using `pull_request` (not `pull_request_target`) means forked-PR runs execute with a read-only token and do NOT receive repository secrets — the safe default. This project has no secrets in the workflow at all (no deploy step), so there is nothing to leak even in the worst case. |
| T-04-01-03 | Tampering | Third-party action supply chain (`actions/checkout`, `actions/setup-node`) | low | accept | Both are first-party, officially maintained GitHub actions pinned to major-version tags (`@v4`). Full-SHA pinning is a stronger option but is accepted as unnecessary at ASVS L1 for first-party actions with no secrets in scope. |
| T-04-01-04 | Information Disclosure | Deleting `netlify.toml`/`wrangler.toml` | n/a | accept | Both files were read in full during planning and contain zero secrets (build/cache-header config only) — their removal and continued presence in git history carry no exposure risk. |
| T-04-01-SC | Tampering | npm / pip / cargo package installation | n/a | n/a | Not applicable — this phase installs no new npm dependency (the CI workflow calls `npm ci` against the existing lockfile; Task 2 removes a devtool script, it adds none). |
</threat_model>
