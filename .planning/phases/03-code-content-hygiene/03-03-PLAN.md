<objective>
Remove the blanket TypeScript opt-out from the contact form's handler module and make it pass
`astro check` under strict mode, by declaring the one genuinely untyped thing it uses: the
Preline-installed `window.HSSelect` global.

Purpose: the contact form is this site's primary lead-generation path and the reason the site
exists commercially, yet its handler module is the single file in an otherwise strict codebase where
type errors cannot be caught at compile time. Requirement TECHDEBT-03.

Output: a new ambient declaration file `themes/lumio/src/types/preline.d.ts`, a fully type-checked
`themes/lumio/src/lib/utils/FormHandle.ts`, and a clean phase-wide build.
</objective>

<threat_model>
Security enforcement is on at OWASP ASVS level 1, blocking on `high`. This plan adds one ambient
type declaration and makes one compile-time-equivalent edit inside a client-side form helper in a
static site with no server runtime. The register below covers the one thing that genuinely matters
here — not breaking the site's only lead-capture path — plus the pre-existing form risks that this
plan deliberately does not change.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| visitor browser -> formsubmit.co | Untrusted visitor input leaves the static site and crosses to a third-party form-relay service over HTTPS; there is no server of ours in the path |
| Preline runtime global -> application code | `window.HSSelect` is installed at runtime by a dynamically imported third-party plugin and consumed by our code with no import-time guarantee that it exists |
