None of them needs to change, and none of them should.

4. **A default parameter value is the wrong shape here — this is the trap.** `function handleDraftPage(pageData, isProd = import.meta.env.PROD)` evaluates the default expression on *every* call that omits the second argument, before the body runs. Under Jest `import.meta.env` is undefined, so that form throws a TypeError even for `{ draft: false }` — breaking the existing passing test. The fallback must be resolved *inside* the body behind a guard.

5. **`Response` is available inside the Jest sandbox.** `jest-environment-node` (Jest 30) copies every `globalThis` own-property except its denyList (`GLOBAL`, `root`, `global`, `globalThis`, `Buffer`, `ArrayBuffer`, `Uint8Array`, `jest-symbol-do-not-touch`); `Response` is a Node 22 global and is not denied. So both `instanceof Response` and `.status` / `.statusText` reads work in tests. If `instanceof` ever proves flaky under the ESM sandbox, `Object.prototype.toString.call(result)` yielding `"[object Response]"` is the fallback — but the `status` / `statusText` assertions are the load-bearing ones either way.

6. **Jest's per-test ✓ lines are NOT printed when output is piped here, even with `--verbose`** (observed: only the summary block appears). Do not gate on `PASS` lines or ✓ marks. Gate on the summary counters, which do print reliably.

7. **`tsconfig.jest.json` / `jest.config.ts` need no changes.** The existing `^@/(.*)$` and `^\.astro/config\.generated\.json$` moduleNameMapper entries already cover this module; it imports nothing.

8. **The IN-01 write-up's alternative fix does not work.** It suggested `jest.replaceProperty(import.meta.env, "PROD", true)`. That call needs `import.meta.env` to be an object, and under Jest it is `undefined` — so it would throw on the argument itself. The injectable-parameter route (what the user asked for) is the only one of the two that actually runs.
